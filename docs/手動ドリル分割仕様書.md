## 1. 背景と目的

ドリル自動分割は「登録済みフィールドの外＋低速度（1.0m/s未満）が60秒以上続く」区間だけを休憩とみなす。そのため次のような記録は複数本に分けられない。

- フィールド内で休憩した（説明を聞く・給水がフィールド内にある など）
- 登録したフィールドが実際の練習範囲より広い
- 休憩中にフィールド外を歩き回っていて、低速度の条件が続かなかった

また、自動検出の結果が少しずれていても、確認画面では「確定する」か「分割しない」しか選べない。

**目的:** コーチが1つの記録の中で区切り位置を自分で指定し、1本以上のドリルを切り出せるようにする。自動検出の結果を手直しすることもできるようにする。1本だけの切り出しで「開始が早すぎた」「終了が遅すぎた」も直せるので、打ち切り機能は廃止する。

---

## 2. 現状の整理

| 機能 | できること | できないこと |
|---|---|---|
| 打ち切り（トリム） | 終了位置を1点決めて、それ以降を除外する | 開始位置の変更、途中区間の切り出し、複数本化 |
| ドリル自動分割 | 検出された休憩で複数本に分け、元に戻せる | 区切り位置の調整、区間の追加・削除 |

自動分割の確定処理（`confirmDrillSplit`）は、休憩区間のリスト（`pendingSplitBreaks`）から区間を作る。そのうえで区間ごとに GPS 点を切り出し、新しいセッションの作成・指標の再計算・Supabase へのアップロード・元セッションの非表示化まで行う。**区間ごとにセッションを作る部分は、手動分割でもそのまま使える。** ただし、休憩区間のリストではドリル同士が直接隣り合う区切りを表せない。そのため確定処理を少し作り替え、ドリル区間のリストを直接受け取れるようにする（§6.2、§9）。

## 3. 方針サマリー

- セッション詳細画面に「**ドリルを切り出す**」ボタンを追加し、専用の編集画面を開く
- 編集画面では、再生位置で「**ここで区切る**」を押して区切り位置を追加する。区切られた各区間を「**ドリル**」か「**休憩（除外）**」に切り替える
- 切り出せるのは**1本以上**。1本だけの切り出しは、従来の打ち切り（終了位置の変更）に加えて開始位置の変更も兼ねる
- 自動検出の候補がある場合は、その結果を初期状態として読み込み、手直しできるようにする
- 確定すると、自動分割と共通の処理で新しいセッションを作る。元に戻す・削除時の扱いも自動分割と同じにする
- 編集中の内容は保存しない。確定するまで元の記録は変わらない
- **打ち切り機能は廃止し、関連するコードもすべて削除する**（§7）

**「区切り位置＋区間の切り替え」方式にする理由:** 区間ごとに開始・終了の2点を決める方式では、操作の回数が倍になる。また区間が重なったり、すき間ができたりしたときの扱いが必要になる。区切り位置で全体を隙間なく分け、各区間を「ドリル／休憩」に切り替える方式なら、区間が重なることはなく、iPhone の小さい画面でも操作しやすい。

## 4. 画面と操作

### 4.1 入口

| 場所 | 表示条件 | 内容 |
|---|---|---|
| セッション詳細画面（今の「この位置で打ち切る」ボタンの位置） | フィールドが選択されている／分割で作られたセッションではない／分割済みで非表示になった記録ではない | 「ドリルを切り出す」ボタン（はさみのアイコンを引き継ぐ） |
| ドリル分割の確認画面（`DrillSplitReviewView`） | 自動検出の候補がある | 「手動で調整する」ボタン。押すと編集画面を開き、自動検出の結果を初期状態にする |

フィールドが選択されていないセッションでは、詳細画面に再生コントロールが出ない。そのため手動分割もフィールドの選択を前提にする（決定事項）。

### 4.2 編集画面「ドリルを切り出す」

上から次の順に並べる。

1. **フィールドマップ**: `DrillSplitFieldMapView` を再利用する。ドリル区間は区間ごとの色の実線、休憩区間はグレーの破線で描く。今の再生位置をマーカーで示す
2. **タイムライン**: 記録全体を1本の横長のバーで表す。区間ごとに色を分け（ドリル＝区間色、休憩＝グレー）、区切り位置に縦線を引く。今の再生位置も縦線で示す
3. **再生位置スライダー**: 詳細画面の再生コントロールと同じ操作感にする。経過時間を表示し、細かく合わせるための「−5秒／＋5秒」ボタンも置く
4. **「ここで区切る」ボタン**: 今の再生位置に区切りを追加する
5. **区間リスト**: 区間ごとに1行で表示する
   - 色の印、「ドリルN」または「休憩」、開始時刻〜（長さ）、距離
   - 「ドリル」と「休憩」を切り替えるスイッチ
   - 行をタップすると、再生位置をその区間の先頭に移す
   - 行の左スワイプで「左の区切りを削除」（隣の区間と1つにする）。先頭の区間には出さない
6. **下部ボタン**（確認画面と同じく `safeAreaInset(edge: .bottom)` に置く）
   - 「N本のドリルを切り出す」（目立つボタン）
   - 「キャンセル」

**よく使う操作の例:**
- 開始が早すぎた → 本当の開始位置で区切り、先頭の区間を「休憩」にする
- 終了が遅すぎた → 本当の終了位置で区切り、末尾の区間を「休憩」にする
- 途中の1本だけ残す → 前後で区切り、前後の区間を「休憩」にする

### 4.3 初期状態

| 状況 | 初期状態 |
|---|---|
| 自動検出の候補がある（確認画面から開いた場合、または詳細画面から開いて候補が残っている場合） | 候補の休憩区間の境目を区切り位置にする。休憩区間は「休憩」、その他は「ドリル」 |
| 候補がない | 区切りなし。全体が1つの「ドリル」区間 |

### 4.4 確定

ボタンを押すと、確認ダイアログを出す。

> N本のドリルを切り出しますか？
> 分割前の記録は「分割前の記録に戻す」でいつでも復元できます。

1本の場合は「ドリルを切り出しますか？」とし、元の記録との違いをメッセージに表示する（廃止する打ち切りダイアログと同じ形）。

> 時間: 25:10 → 18:40
> 距離: 3.21km → 2.48km

確定後は詳細画面を閉じて一覧に戻る（自動分割の確定後と同じ）。

## 5. 入力チェック

| 条件 | 扱い |
|---|---|
| 「ドリル」の区間が1本もない | 確定ボタンを無効にし、「ドリルを1本以上選んでください」と表示する |
| 区切りがなく、全体が1本の「ドリル」（元の記録と同じ） | 確定ボタンを無効にする（変化がないため） |
| 60秒未満の「ドリル」区間がある | 確定ボタンを無効にし、該当する行に「短すぎます（60秒以上）」と表示する |
| 区切り位置が既存の区切りや記録の先頭・末尾から5秒以内 | 追加しない（ボタンを無効にする） |
| 区間内の GPS 点が少なく、指標を計算できない（`computeSegmentStats` が nil） | 60秒未満と同じ扱い |

**60秒未満を黙って捨てない理由:** 自動分割では、`segmentRanges` が60秒未満の断片を自動で捨てている。手動では、コーチが「ドリル」と指定した区間が知らないうちに消えると混乱するため、捨てずに確定前に知らせる。

## 6. データの扱い

### 6.1 編集中の状態
編集画面の中だけに持つ（保存しない）。

```swift
/// 区切り位置（先頭点からの経過秒、昇順、0 と末尾は含まない）
var cutOffsets: [TimeInterval]
/// 区間ごとのドリル/休憩（要素数 = cutOffsets.count + 1）
var isDrill: [Bool]
```

タイムラインは**生データ全体**（先頭点〜最後の点）を表す。

### 6.2 確定時の変換
「ドリル」の区間をそのままドリル区間のリストにし、共通の確定処理に渡す。

例: 区切り位置 `[300, 420, 900]`、区間 `[ドリル, 休憩, ドリル, ドリル]`、全体 1200秒
→ ドリルは `0〜300`／`420〜900`／`900〜1200` の3本

`420〜900` と `900〜1200` のようにドリル同士が隣り合う区切りは、休憩区間のリスト（`pendingSplitBreaks`）では表せない。このため確定処理は、休憩区間ではなく**ドリル区間のリストを受け取る**形にする（§9）。

### 6.3 作られるセッション
自動分割と同じにする。

- 名前: 2本以上なら `元の名前 - ドリルN`。**1本だけなら元の名前をそのまま使う**（実質的に元の記録の範囲を直しただけなので）
- 開始時刻: 元の開始時刻＋区間の開始秒
- 距離・速度・スプリント・アジリティ・スタミナ低下などは、区間の GPS 点から計算し直す
- 心拍数: 区間内で心拍データがある最後の点の値
- 消費カロリー: 1本だけの場合も含めて設定しない（区間ごとの正確な値が出せないため。自動分割と同じ判断）
- `splitFromSessionId` に元セッションの id を入れる
- 元セッションは `supersededBySplit = true` にし、`pendingSplitBreaks` は nil に戻す

手動か自動かの区別は保存しない。確定後の扱い（元に戻す・削除）がまったく同じだからである。

**1本だけの切り出しでも新しいセッションを作る理由:** 元のセッションを直接書き換えると、元に戻すための情報を別に持つ必要がある。2本以上の場合と同じ「元を非表示にして新しいセッションを作る」形にすれば、「分割前の記録に戻す」がそのまま使える。

## 7. 打ち切り機能の廃止

1本だけの切り出しで同じことができるため、打ち切り機能は廃止する。

TestFlight で配信したテスターは、2026-10-22 時点で誰もインストールを完了していない。打ち切り済みのセッションを持つ利用者がいないため、互換用のコードは残さず**すべて削除する**。

### 7.1 削除するもの
- `TrainingSession.effectiveEndOffset` と `isTrimmed`
- `SessionDataManager` の `applyTrim`・`trimmedPoints`・`getEffectiveGPSData`（呼び出し側は `getGPSData` に置き換える）
- セッション詳細画面の「この位置で打ち切る／この位置に変更」ボタン、打ち切り中の表示と「元に戻す」、打ち切り関連の確認ダイアログ
- `FieldPositioningView` の `effectiveCutoffIndex`（打ち切り位置以降を薄く描く処理）
- その他、打ち切りを参照している箇所（`SprintMeasurementView`、`ViewsNicknameGeneratorView` など）

Supabase には打ち切りの情報を送っていないため、サーバー側の変更はない。

### 7.2 開発用端末のデータ
開発者の実機に打ち切り済みのセッションが残っている場合、削除後は保存済みの `effectiveEndOffset` が読み込まれなくなる（JSON の不明なキーは無視されるため、読み込みエラーにはならない）。軌跡は生データ全体が表示される一方、時間・距離などは打ち切り時に上書きした値のまま残り、表示が食い違う。開発データのみの問題なので移行処理は作らず、該当セッションは削除するか、「ドリルを切り出す」で切り出し直す。

## 8. 既存機能との関係

| 機能 | 扱い |
|---|---|
| 自動分割の候補 | 手動で確定したら、候補（`pendingSplitBreaks`）は消える。キャンセルした場合、候補はそのまま残す |
| 分割前の記録に戻す（`restoreSplit`） | 変更なし。手動で切り出したセッションにも同じバナーが出る。1本だけ切り出した場合も同じく元に戻せる |
| 削除時の道連れ（最後の1本で元記録も削除） | 変更なし。1本だけ切り出したセッションを削除すると元の記録も削除され、その前に既存の確認ダイアログが出る |
| フィールド登録・変更時の自動再解析 | 切り出し元のセッションは `supersededBySplit = true` なので、再解析の対象にならない（変更なし） |
| 分割で作られたセッションの再分割 | v1 では入口を出さない。やり直したいときは「分割前の記録に戻す」の後に切り出す |

## 9. 実装方針

### 9.1 変更・追加するファイル

| ファイル | 内容 |
|---|---|
| `DrillSplitDetector.swift` | 区切り位置と区間種別からドリル区間を作る純粋関数を追加する（例: `manualRanges(cutOffsets:isDrill:totalDuration:)`）。休憩区間から区切り位置と区間種別を作る関数も追加する（初期状態用） |
| `SessionDataManager.swift` | `confirmDrillSplit` の本体を「ドリル区間のリストを受け取る関数」（例: `applyDrillSplit(for:ranges:)`）に切り出す。自動分割はこれまで通り `segmentRanges` で区間を作ってから呼ぶ。手動分割は編集結果の区間をそのまま渡す。1本の場合は元の名前を使う |
| `DrillSplitManualEditView.swift`（新規） | §4.2 の編集画面 |
| `DrillSplitFieldMapView.swift` | 再生位置のマーカー表示を追加する（任意の引数にして、確認画面からは渡さない） |
| `ViewsSessionDetailView.swift` | 打ち切り関連の UI をすべて削除し、「ドリルを切り出す」ボタンと画面表示を追加する |
| `DrillSplitReviewView.swift` | 「手動で調整する」ボタンを追加する |
| `ModelsTrainingSession.swift` ほか §7.1 の各ファイル | 打ち切り関連のコードを削除する |

### 9.2 打ち切りとの整合（既存の問題）
今の `confirmDrillSplit` は、打ち切り前の全 GPS 点（`getGPSData`）から休憩を検出・切り出している。一方、区間の末尾には打ち切り後の `session.duration` を使っている。この組み合わせでは、打ち切り位置より後に休憩が検出されると、打ち切った後の区間がドリルとして切り出されることがある。

打ち切り機能をなくせば `session.duration` は常に生データ全体の長さになるため、この問題は打ち切り機能の削除と同時に解消する。個別の修正は不要。

## 10. テスト

### 10.1 ユニットテスト（`DrillSplitDetectorTests` に追加）
- 区切りなし → ドリル1本（全体）
- 先頭だけ「休憩」 → 1本（開始位置の変更）
- §6.2 の例（休憩1つ＋ドリル同士が隣り合う）→ 3本
- 休憩が連続する（区切り2つをまたぐ休憩）→ 1つの休憩としてまとめる
- 先頭・末尾が休憩 → ドリルに含まれない
- 休憩区間 → 区切り位置・区間種別への変換と、元に戻したときの一致
- 打ち切り関連のテストがあれば削除する

### 10.2 実機での確認
- フィールド内で休憩した練習を手動で3本に分割し、各ドリルの距離・時間・心拍数が妥当か確認する
- 開始・終了の両方を詰めて1本だけ切り出し、名前が元のままで、指標が切り出した範囲の値になることを確認する
- 自動検出の候補を手直しして確定し、さらに「分割前の記録に戻す」で元に戻ることを確認する
- 打ち切り関連の表示がどこにも出ないことを確認する

## 11. 対象外（今回は実装しない）

- 分割で作られたセッションを開いたまま、分割をやり直す編集（いったん元に戻してから切り出す運用で代用する）
- ドリルごとの名前の入力（確定後に既存の名前変更で対応する）
- 速度グラフや心拍グラフをタイムラインに重ねる表示
- 編集途中の保存
- フィールド未選択のセッションでの切り出し
